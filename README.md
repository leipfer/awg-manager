# AmneziaWG Manager

**Графическое управление туннелями AmneziaWG для Linux**

[![Build](https://github.com/leipfer/awg-manager/actions/workflows/build.yml/badge.svg)](https://github.com/leipfer/awg-manager/actions)
[![License: GPL v3](https://img.shields.io/badge/License-GPLv3-blue.svg)](LICENSE)
![GTK4](https://img.shields.io/badge/GTK4-libadwaita-purple)
![Ubuntu](https://img.shields.io/badge/Ubuntu-24.04%20%7C%2026.04-E95420)

Включение и выключение туннелей, мониторинг в реальном времени,
раздельное туннелирование и значок в трее — без единой команды в терминале.

</div>

---

## Возможности

- **Управление туннелями** — все конфиги из `/etc/amnezia/amneziawg` списком с переключателями
- **Только один туннель одновременно** — при включении нового предыдущий отключается автоматически
- **Мониторинг в реальном времени** — handshake, принято/передано, скорость, endpoint, адрес, DNS, MTU, AllowedIPs
- **График скорости** приёма и передачи
- **Раздельное туннелирование** по IP, подсетям и **доменам** — режимы «только список» и «кроме списка», без правки ваших конфигов
- **Гибкая настройка интерфейса** — любую строку статистики и любой блок можно скрыть
- **Значок в трее** с быстрым переключением и счётчиками
- **Автозапуск** туннеля при загрузке системы
- **Журнал** юнита прямо в окне
- **Без ввода пароля** — авторизация через polkit для активной локальной сессии

## Установка

```bash
sudo apt install ./awg-manager_1.3.0_all.deb
```

Затем **перелогиньтесь** (или `sudo systemctl restart polkit`), чтобы применилось правило polkit.

Если значок в трее не появился:

```bash
sudo apt install gir1.2-ayatanaappindicator3-0.1
```

Запуск: **Приложения → AmneziaWG Manager** или `awg-manager` в терминале.
Значок в трее стартует автоматически при входе в систему.

### Удаление

```bash
sudo apt remove awg-manager
```

## Раздельное туннелирование

Меню → **Раздельное туннелирование**.

### По IP, подсетям и доменам — поддерживается полностью

| Режим | Поведение |
|---|---|
| **Выключено** | весь трафик идёт через VPN |
| **Только список** | через VPN идут **только** указанные адреса, остальное напрямую |
| **Кроме списка** | указанные адреса идут **напрямую**, остальное через VPN |

В список можно вводить:

- подсети: `192.168.0.0/16`
- отдельные адреса: `8.8.8.8`
- **домены и ссылки**: `chatgpt.com`, `https://chatgpt.com/c/123` — приложение
  само определит IP-адреса

Домены разрешаются в IP при каждом применении **и при каждом подключении
туннеля**, поэтому список не устаревает. Запросы к DNS идут в обход туннеля
(через `dig` к публичным резолверам), чтобы получить адреса, которые видит ваш
провайдер, а не VPN-сервер.

#### Как это работает

`awg-quick` при `AllowedIPs = 0.0.0.0/0` не кладёт default в таблицу `main`,
а создаёт политику маршрутизации:

```
32764: from all lookup main suppress_prefixlength 0
32765: not from all fwmark 0xca6c lookup 51820   <- перехватывает весь трафик
```

Приложение ставит свои правила с **меньшим** приоритетом (18000 и 18500),
поэтому они срабатывают раньше перехвата:

```
18000: to <адрес> lookup 51821    только список: адрес → в туннель
18000: to <адрес> lookup 51822    кроме списка: адрес → напрямую
18500: from all   lookup main     только список: остальное → мимо туннеля
```

Ваши файлы конфигурации при этом **не изменяются**.

#### Наборы

Встроенные: **Российские сервисы (IP)** — один объединённый список из банков,
госуслуг, Яндекса, VK, маркетплейсов и операторов; **Российские сервисы
(домены)** — те же сервисы доменами, всегда актуальные; **Локальные сети**.

**Свои наборы.** В группе «Наборы» первая строка — «Создать свой набор»:
сохраняет текущий список под своим именем. Готовый набор можно переименовать
или перезаписать (кнопка с карандашом) и удалить (корзина, с подтверждением).
Свои наборы показываются выше встроенных.

Импорт и экспорт текстовым файлом — в меню окна; формат совместим со
списками с `iplist.opencck.org`. Наборы хранятся в
`~/.config/awg-manager/sets.json`.

#### Если что-то не работает

Меню → **«Проверить маршрут»** покажет, куда реально пойдёт трафик
к сайту или адресу. В терминале то же самое:

```bash
ip route get $(getent hosts chatgpt.com | awk '{print $1}' | head -1)
sudo /usr/libexec/awg-manager/awg-split show | python3 -m json.tool
```

Учтите: крупные сайты живут на CDN с десятками адресов, и IP меняются.
Один домен не всегда покрывает весь сервис — иногда нужны подсети целиком.
Браузер к тому же кеширует DNS и соединения: после смены правил перезапустите
его или откройте страницу в приватном окне.

### По приложениям — ограничение платформы, не приложения

Сам AmneziaVPN **не умеет** разделять по приложениям на Linux, macOS и iOS —
[официальная документация](https://docs.amnezia.org/documentation/instructions/vpn-split-tunneling/)
отмечает поддержку только для Windows и Android. Причина в том, что у ядра Linux нет
понятия «трафик приложения»: сокет принадлежит процессу, а маршрутизация работает
с адресами и метками пакетов.

Технически задача решается через cgroup v2 + nftables (так делает Mullvad), но это
означает постоянно работающий демон, который отслеживает запуск процессов и переносит
их в нужную cgroup. Для приложения такого масштаба это лишняя сложность и заметный
источник ошибок, поэтому реализован более простой и предсказуемый подход.

**Запуск отдельного приложения в обход туннеля:**

```bash
sudo awg-setup-direct        # однократно: создаёт системного пользователя
awg-run-direct firefox       # Firefox пойдёт мимо VPN
awg-run-direct telegram-desktop
```

Работает через `ip rule ... uidrange`: трафик указанного пользователя маршрутизируется
в обход туннеля. Способ надёжный и не требует фонового демона, но у приложения будет
отдельный домашний каталог и профиль.

На практике разделение по IP закрывает большинство сценариев: если добавить подсети
российских сервисов в режим «кроме списка», банки и госуслуги пойдут напрямую вместе
со своими мобильными и десктопными клиентами.

## Права root без пароля

Пароль **не запрашивается**. Привилегированные операции выполняет
`/usr/libexec/awg-manager/awg-helper`, запускаемый через `pkexec`.

Правило `49-awg-manager.rules` разрешает действие `org.awgmanager.manage`
без аутентификации, если одновременно верно:

- сессия **локальная** и **активная** (не SSH, не фоновая);
- пользователь состоит в группе `sudo`, `adm` или `wheel`.

Мониторинг использует **один долгоживущий** привилегированный процесс, а не новый
`pkexec` каждую секунду.

### Безопасность

- Хелпер принимает только фиксированный набор действий; произвольные команды выполнить нельзя
- Имя интерфейса проверяется регуляркой **и** обязано соответствовать существующему
  файлу `.conf` — path traversal невозможен
- Приватные ключи никогда не покидают хелпер: первое поле `awg show dump` отбрасывается,
  из конфига читаются только `Address`, `DNS`, `Endpoint`, `MTU`
- `systemctl` и `ip` вызываются по абсолютным путям с очищенным `PATH`

Чтобы **всегда спрашивать пароль**, удалите правило:

```bash
sudo rm /usr/share/polkit-1/rules.d/49-awg-manager.rules
sudo systemctl restart polkit
```

## Соответствие командам терминала

| Раньше | Теперь |
|---|---|
| `sudo systemctl start awg-quick@awg0` | переключатель у `awg0` |
| `sudo systemctl stop awg-quick@awg0` | тот же переключатель |
| `watch -n 1 'sudo awg show \| grep -E "handshake\|transfer"'` | блок «Статистика соединения» |
| `sudo systemctl enable awg-quick@awg0` | «Автозапуск при загрузке системы» |
| `journalctl -u awg-quick@awg0` | меню → «Показать журнал» |

## Структура

```
/usr/bin/awg-manager                  главное окно (GTK4)
/usr/bin/awg-manager-tray             значок в трее (GTK3)
/usr/bin/awg-run-direct               запуск приложения мимо VPN
/usr/bin/awg-setup-direct             однократная настройка обхода
/usr/libexec/awg-manager/awg-helper   привилегированный backend
/usr/libexec/awg-manager/awg-split    раздельное туннелирование
/usr/share/awg-manager/awgmanager/    модули Python
/usr/share/polkit-1/…                 действие и правило polkit
/etc/awg-manager/split.json           настройки раздельного туннелирования
~/.config/awg-manager/settings.json   настройки интерфейса
```

Окно и трей — **разные процессы**: AppIndicator существует только для GTK3,
а окно написано на GTK4, и в одном процессе эти библиотеки несовместимы.
Закрытие окна не выключает туннель и не убирает значок.

## Диагностика

```bash
# версии GTK/libadwaita, доступность API, проверка pkexec
awg-manager-doctor

# состояние глазами хелпера
sudo /usr/libexec/awg-manager/awg-helper status | python3 -m json.tool

# правила раздельного туннелирования
sudo /usr/libexec/awg-manager/awg-split show | python3 -m json.tool
ip rule show

# запуск окна с выводом ошибок
awg-manager
```

| Проблема | Решение |
|---|---|
| «Конфигурации не найдены» | в `/etc/amnezia/amneziawg` нет `*.conf`. Имя туннеля = имя файла: `awg0.conf` → `awg-quick@awg0` |
| «Запрос прав отклонён» | перелогиньтесь; проверьте `id -nG` (нужна группа `sudo`) и что сессия локальная |
| Нет значка в трее | `sudo apt install gir1.2-ayatanaappindicator3-0.1`; в чистом GNOME нужно расширение AppIndicator Support |
| Туннель не поднимается | меню → «Показать журнал» |
| После split нет интернета | меню → «Раздельное туннелирование» → «Выключено» → «Применить», либо `sudo /usr/libexec/awg-manager/awg-split clear` |
| Сайт из списка ведёт себя не так | меню → «Проверить маршрут»; перезапустите браузер (кеш DNS) |
| Окно не открывается / приложение подвисает | `awg-manager-doctor` покажет, каких API не хватает; запустите `awg-manager` в терминале и пришлите traceback |

## Разработка

```bash
git clone https://github.com/leipfer/awg-manager.git
cd awg-manager

# запуск из исходников
AWG_HELPER=$PWD/helper/awg-helper PYTHONPATH=$PWD/src python3 -m awgmanager.app

# тесты
python3 -m unittest discover -s tests -v

# сборка пакета
./build.sh
```
